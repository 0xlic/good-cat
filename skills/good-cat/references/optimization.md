# 模板继承和无中断优化约定

## 网络连续性优先

模型可能依赖当前 FlClash 出口。标准流程只读数据库、使用私有草案测速和导出，不退出/重启/切换 FlClash，不调用 `apply/restore`，不在线写数据库。底层离线写入脚本仅保留为独立维护工具，不代表优化流程可以使用它。

不能通过取消 offline 检查实现在线写库：数据库事务并不能解决应用内存缓存覆盖、配置重新生成及当前选择同步问题。没有验证过的无中断创建方式时，报告阻塞并保留计划。

## 模板与允许的变更

`create-plan` 必须显式提供订阅 ID 和参考 custom 配置 ID。保留四组名称（含图标）、顺序、测试 URL、额外组参数、规则及规则集顺序、profile overrides；不复制旧行 ID 或 selected_map/unfold_set。

明确变化：新配置名称；四组绑定所选订阅 label 并取消 include-all 系列字段；草案三个业务组 filter 暂空；最终替换为合格节点精确白名单。节点筛选的 hidden/exclude-filter 保留原样，不能自动散布到业务组。不自行增加 interval/tolerance、Apple/Microsoft 规则或把 RULE_SET 改写为域名模板。

所有 `--out` 以私有权限新建，不覆盖旧文件。产物仅放在已忽略的 `.flclash-local/`；不得上传缓存、数据库或节点凭据。

## Python 自动测速

使用 `benchmark.py`，由 `goodcat.py benchmark --plan <草案>` 调用，**不需要先创建数据库配置**。无需核心 API、controller 或 secret。

依赖：Python 3.9+，可信独立 Mihomo CLI；YAML 缓存使用 PyYAML safe_load（JSON 无第三方依赖）。缺失依赖先询问用户，使用项目虚拟环境/核实官方发布来源，不静默安装。

默认读取数据库同级 `profiles/<订阅ID>.yaml`，模型可核实文件归属后指定 `--nodes-file`。需要包含 proxies 数组的 Clash YAML/JSON，最大32MB；不以运行配置、另一订阅或原始 base64/URI 文件替代，不自动下载订阅。

每个节点启动一个独立临时核心：私有目录、回环随机认证 HTTP 代理、MATCH 固定到节点。controller、TUN、DNS服务禁用，不使用系统HTTP代理变量。仅复制节点定义，不复制订阅全局配置。不支持链式代理时记为失败，无直连回退。

Python 通过显式 CONNECT、校验证书的 TLS、HTTPS GET 请求各组原始测试 URL，用 perf_counter 计时至响应头。不含核心启动时间，不读取正文、不复用连接、不跟随重定向。默认接受HTTP 2xx/3xx，403/429等为失败。不等同于核心delay、带宽、出口地理或AI解锁验证。

默认3轮，按节点顺序运行，每轮三个地址，轮间1秒。所有轮次成功且**每轮 <=600ms**才合格，再按中位数排序。报告含全部节点、每轮耗时、HTTP状态、失败类型、URL、缓存SHA-256、数据库指纹、订阅ID和时间。

节点完成、异常或Ctrl+C后自动清理本次进程和临时文件；强制杀死脚本或系统崩溃不保证清理。不中止其他核心进程。现有TUN/VPN可能影响临时核心出站，应记录环境，不能以关闭现有代理来改善测量条件。

## 精确白名单而非仅地区正则

模型逐组审阅全部合格节点，按延迟取最先出现的两个不同地区；只有一个时说明，无合格地区则停止交付。地区内置模式只用于识别候选节点，不直接作为最终 filter。

`filter-plan` 重新核对报告的provider、base、URL、每轮延迟/状态/错误，筛选“入选地区 ∩ 每轮<=600ms合格节点”，生成 `^(完整节点名1|完整节点名2)$`。转义RE2正则元字符，不生成Python特有的标点转义。保留其他组字段和规则，不会纳入同地区未达标或新增节点。

报告是本地工具产物而非不可伪造证据；不能手动修改报告以通过验收。订阅缓存变化、数据指纹变化、URL变更时重新生成草案和测速，不修改base。订阅刷新后名称可能变化，应重新测试。

## 导出边界

`export-config` 拒绝空filter草案。当前只支持可直接表达的规则及标准覆盖键转换；遇到RULE_SET或不支持的覆盖字段时拒绝输出，不丢弃或降级。file provider路径基于FlClash工作目录，移动文件前须核对解析位置。

**尚未实现应用规则提供者的无损编译，也未实现运行中FlClash的无中断custom创建。** 含规则集的模板目前仅能完成最终计划生成和check，不能宣称已经创建可用配置。计划JSON不是Clash配置，不可直接导入；导出配置也不能未经核对就宣称对应数据库custom。交付必须区分各阶段状态。
